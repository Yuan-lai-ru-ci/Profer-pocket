# Profer Android 设计系统

> 2026-10-30 系统化重构后的单一依据。改动 UI 前先读这一页；token 数值以
> `core/designsystem/src/main/kotlin/com/profer/pocket/designsystem/theme/` 为准，
> 本文只解释角色和约束，不复制第二份真值。

## 0. 原则

1. **同一件事只有一个样子**：圆键、胶囊、分组卡、输入框、消息、顶栏都由公共组件或
   M3 形状角色定义，页面不自拼圆角、描边、阴影与透明度。
2. **画布安静，操作浮起**：页面背景只做同源色过渡；可操作的东西（输入区、圆键、
   胶囊）用内容面 + 细边线 + 极轻投影浮起，不靠大色块抢注意力。
3. **层级靠色阶和留白**：相邻表面明度差控制在 4–8%，不用重边框、重阴影堆层级。
4. **一个屏幕一个主动作**：发送、连接、新建、允许各自是唯一主操作；其余动作退成
   安静胶囊或次级文字。
5. **状态必须有出路**：空、加载、错误、离线都要有明确下一步；错误不用品牌色顶替。
6. **与桌面同源不同形**：同一套品牌与语义色，布局按手机重构，不把桌面三栏等比缩小。

## 1. Token

### 1.1 色彩（`Color.kt`）

| 角色 | 浅色 | 深色 |
|---|---|---|
| background / surface | `#F7F5F2` | `#191715` |
| surfaceContainerLow（内容面） | `#FCFAF7` | `#211F1C` |
| surfaceContainerLowest（浮层/圆键） | `#FFFDFC` | `#121110` |
| surfaceContainer（分段轨道） | `#EFECE7` | `#292724` |
| surfaceContainerHigh（抽屉/选中行） | `#E8E3DC` | `#2E2C28` |
| onSurface | `#322F2A` | `#ECEBE9` |
| onSurfaceVariant | `#66635C` | `#AAA7A1` |
| outlineVariant | `#E7E1D9` | `#312F2B` |
| primary（陶土） | `#846558` | `#B4998E` |
| error | `#B93A32` | 由 M3 dark scheme 提供 |

规则：

- 主操作只有陶土一支；品牌标记固定墨色/反白，不跟主色走。
- 语义状态（成功、警告、错误、代码块）走 `ProferThemeExtras.semantic`，不手拼 alpha。
- 不启用动态取色。`UiDesignTokensTest` 锁定正文、次要文字、主操作与状态容器的 AA 对比度。
- 启动窗口底色与首帧主题一致（`values/colors.xml`、`values-night/colors.xml`）。

### 1.2 排版（`Type.kt`）

- 统一无衬线 `FontFamily.Default`；`ProferSerif` 等旧符号是兼容别名，不得再引入第二套字族。
- 全部映射到 M3 type scale；正文 15sp/24sp，辅助最小 12sp，代码 12.5sp 等宽且横向滚动。
- 标题靠字号 + 颜色 + 间距分层，不叠加字重。

### 1.3 间距与尺寸（`Dimens.kt`）

- 4dp 栅格：`ProferSpacing` 4/8/12/16/24/32/48。
- 页面水平 16dp；组间 24dp；同组 8–12dp。
- `ProferSizes.minTouchTarget = 48dp`：所有可点区域至少这个尺寸；圆键视觉 40dp、图标 22dp。
- `contentMaxWidth = 760dp`：平板/横屏内容居中，不无限拉宽。
- `composerMinHeight = 56dp`；`hairline = 1dp`；`floatingElevation = 2dp`（深色下不投影，靠色阶）。

### 1.4 形状（`Shape.kt`）

`MaterialTheme.shapes` 五档，语义固定：

| 档 | 半径 | 用途 |
|---|---|---|
| extraSmall | 8 | 行内标签、小色块 |
| small | 12 | 小按钮、提示条、内嵌说明 |
| medium | 16 | 分组卡、代码块、工具卡 |
| large | 20 | 用户气泡、审批卡 |
| extraLarge | 28 | 输入区、对话框、底部弹层、胶囊按钮 |

胶囊与圆键使用 `CircleShape`。新增代码不得直接写 `RoundedCornerShape(n.dp)`；先找语义档。

## 2. 材质

- `Modifier.proferBackdrop()` / `ProferBackdrop`：画布底色 + 极轻同源渐变；无实时模糊、
  无图片依赖，低端机与深色模式同构。
- `ProferChrome`：圆键/胶囊的浮层材质（`surfaceContainerLowest` + 细边线 + 轻投影）。
  一个元素只套一层；`ProferIconAction` 内部已包含它，页面不要再包一次。
- 内容卡直接用 `surfaceContainerLow` + `outlineVariant` 边线，不加阴影。

## 3. 组件规则

### 3.1 顶栏

- `ProferHeaderRow` 统一状态栏 inset、水平留白与 48dp 最小高度；页面只填业务槽位。
- 菜单/返回/更多都是 `ProferIconAction`；标题在中间，单行省略。
- 聊天标题放浮动胶囊里，与输入区、圆键同一材质；子会话面包屑可点回母会话。
  Agent 对话与 Chat 对话共用同一几何与字号，不再各自拼背景。
- 上下文用量环只在有数据（`contextUsage` 或 `contextWindow`）时出现；新会话首条消息前不画空环。

### 3.2 输入区（`ProferComposer`）

按 dsh-go 的输入条几何复刻（尺寸来自其 `composer.dart`）：

- 胶囊：圆角 28dp，四周内缩 8dp，单行高 **8 + 40 + 8 = 56dp**；圆角 28 = 键半径 20 + 8，
  两端圆键与胶囊同心。
- 两端各一颗 **40dp 圆键**：左侧附件/工具用 `onSurface 6%` 淡底 + 22dp 图标；
  右侧发送键始终存在——空输入是 `onSurface 12%` 底 + 38% 箭头，有字或运行中变实心主色，
  运行中图标换成停止。
- 文字与两端圆键共用 40dp 中线：输入区用 `heightIn(min = 40.dp)` 的居中容器承载文本，
  不再用「行高 + 上下 padding」凑高度（行高随字体度量变化，会与圆键中线错开）。
  1–6 行自适应；多行时容器向下长，Row 底部对齐让圆键继续贴底。
- 无草稿时发送键不可点，但保留圆形占位，不消失、不换位。
- **左侧「+」是唯一入口**：点开是底部弹层，**不写标题和说明**——这一层只有动作和当前值。
  顶部是动作方块（60dp 圆角块 + 下方标签）：相册（Agent/Chat 都有）、工具（仅 Chat）；
  下面 `本轮` 分组是一张卡片，三行模型 / 预设 / 权限，右侧当前值 + chevron，行高 56dp、分隔线内缩。
  选择器不再单独占输入条上方一行——那一行既多一层浮块，又和胶囊脱节。
- `imePadding()` / `navigationBarsPadding()` 由输入组件拥有，页面外壳不要重复叠加。

> 取舍：端键视觉与热区都是 40dp，低于本规范其他位置的 48dp。这是为复刻参考几何
> （56dp 胶囊 + 40dp 端键）主动让位；胶囊纵向仍有 56dp 可触区域。若后续要回到 48dp，
> 胶囊会变成 64dp，需要整体重排。

### 3.3 消息流

- 用户消息：右对齐气泡，`MaterialTheme.shapes.large`，`surfaceContainerHigh`。
- 助手消息：无气泡通栏，长文优先；思考与工具调用默认收起，可展开。
  - 思考折叠行：`surfaceContainerHigh` 圆角行，图标 + 「思考 · 首行摘要」+ chevron；展开后缩进正文，不画竖线。
  - 工具行：无边框，图标底 + 「标题 · 目标」+ 状态 + chevron；展开后分「参数 / 结果 / 错误」三块，错误用 `errorContainer`。
- 系统回执：居中低对比胶囊，不构成一轮对话。
- 流式光标只做透明度呼吸，不做缩放/弹跳，行高稳定。
- 列表 key 稳定；用户上滑阅读时不抢滚动，只显示「回到最新」；自己发送的消息必须回到底部。
- 纯工具回合没有正文块时不显示复制操作，避免一个复制空串的死图标。
- 键盘弹起后等 IME 动画结束再锚一次底部，最后一行不能被输入条盖住。

### 3.4 欢迎与四态

- 有会话：问候 + 一句说明 + 2×2 建议胶囊；建议只填草稿，不自动发送。
- 无会话：先给「新建会话/新建对话」一个主动作，建议不出现（避免写入不存在的草稿）。
- 离线：原位替换为「连接电脑」一个恢复操作，不同时叠加离线条。
- 加载：骨架/进度 + 取消；错误：原因 + 重试；空：一句人话 + 一个下一步。

### 3.5 抽屉

- 头部只有「品牌 + 模式 + 搜索 + 新建」，不放统计副标题。
- **顶栏是一条 40dp 的齐平带子**：模式胶囊、搜索圆键、新建圆键的可见高度都是
  `ProferSizes.actionVisual`（40dp），三者中线与品牌行同一条；48dp 只做热区。
  之前三者分别是 36 / 48 / 40，即使中线对齐也看着参差。
- Agent/Chat 用一个按钮切换：`DrawerModeButton` 显示当前模式（⇄ Agent / ⇄ Chat），点按切换；
  不再占一整行。大字号（≥1.3×）时按钮自动落到第二行，避免挤扁品牌字。
  1.3× 是实测阈值：再小一档「Profer」就会被切掉半个字。
- 项目名与会话标题共用同一条文本基线：chevron 占 20dp，会话起点 20dp（子会话 36dp）。
- 会话行默认单行 48dp（Android 单行列表最小触控高度）：标题占剩余宽度，右侧依次是项目名（跨项目
  分组时才有）、状态点、时间、子会话开关；不再为时间单独占一行。
- 大字号（≥1.5×）自动退回两行：标题可换行，时间与子会话开关落到第二行。
- 选中态用 `surfaceContainer` 圆角块，不用左侧竖条、不用主色蒙层。
- 子会话开关是行内次级控件，32dp 高；大字号（≥1.5×）时移到时间行，避免挤压标题。
- 底部停靠区是一条紧凑状态胶囊（40dp 视觉 / 48dp 热区）+ 设置圆键，不再占满整行。
- 所有列表行、齿轮、圆键至少 48dp；长按操作保留触感反馈。
- 返回手势优先关闭抽屉；预测性返回跟随手指。

### 3.6 设置与连接

- 设置：分类 label + 分组内容面；主题纵向单选、开关整行可点、长版本信息可换行。
- 连接：已连接详情、扫码/手动入口、真实连接骨架、错误原因与恢复动作；
  不编造分步进度。连接中可取消，失败可重试。
- 内容卡（设置分组、连接卡、设备卡、说明卡）深色下用 `surfaceContainerLow`，
  不用 `surfaceContainerLowest`：后者比画布暗，整页会像挖出一堆黑洞。
  浮层（圆键、胶囊、输入条、弹层）走 `proferFloatingSurface()`。
- 连接设备卡：空地址不占一行；字号 ≥1.3× 时图标顶部对齐，不夹在两行中间。
- 扫码页：相机权限说明 + 失败可见提示 + 返回手动连接入口。

### 3.7 平板、横屏与折叠屏

- 断点沿用 M3：`< 600dp` 单栏（手机竖屏、折叠态），`600–840dp` 中屏，`≥ 840dp` 宽屏。
  但**是否分栏不看断点，看对话区还剩多宽**：`isTwoPane = 非 Compact && 宽度 ≥ 688dp`
  （= 200 列表下限 + 8 栏缝 + 420 对话区下限，后者与桌面 `CONVERSATION_MIN_WIDTH` 同值）。
  640dp 小屏横屏若强分栏，内容区只剩 345dp，比竖屏 360dp 还窄，是「伪桌面」。
- **侧栏宽度按比例给，对话区永远占多数**：目标 28%，同时夹在「对话区 2/3–4/5」之间，
  上限 320dp、下限 200dp。781dp 手机横屏侧栏 219dp（对话 72%），
  1280dp 平板封顶 320dp（对话 75%），688dp 双栏下限 200dp（对话 70%）。
  这段区间有 `TwoPaneSpecTest.conversation_keeps_two_thirds_to_four_fifths` 守着。
- 层级：**对话面铺满整屏，侧栏是浮在左侧的一张圆角小卡**（桌面 AppShell 的关系）。
  侧栏 20dp 圆角（画面里唯一的大圆角，16dp 太收敛）、最亮一级底色 + 一条极淡描边，
  与屏幕边留 8dp（短屏 4dp）；卡片整体让开状态栏，顶部按钮与对话标题同一条基线。
  对话面不包任何卡片，顶栏/消息/输入条直接落在纸面上。
  不要再把两栏各自包成一张卡：那样窗口边缘、两栏之间会漏出四五条同宽的缝，看着像三块板。
- 双栏时顶栏左侧键是「收起/展开列表栏」，不再打开抽屉；抽屉状态归零，返回手势不再拦截。
- **侧栏 260–340dp（平板横屏实测 314dp）的列表头**：品牌字保留，模式胶囊去掉 ⇄ 装饰图标。
  1.0× 下「Profer + ⇄Agent + 搜索 + 新建」要 296dp，实际只有 282dp，品牌字会被压成「Pr…」；
  收掉图标把 26dp 还给品牌字（1.3× 时胶囊本来就会落到第二行，不受影响）。
  200–260dp 才继续收掉品牌字与标记。
- 列表栏可收起：收起后宽度动画收到 0（240ms），内容区真的变宽，列表行不参与组合。
  收起态顶栏换成 `ViewSidebar` 图标把列表叫回来；姿态由宿主（NavHost 外）持有，
  Agent / Chat 共用一份，旋转与进出设置页不重置。
- 横屏单栏（窄横屏、分屏）的抽屉改成**定宽覆盖式侧栏**：`min(320, 宽 × 1/3)`，
  内容不动、加一层 scrim，和桌面版拉开侧栏的关系一致。竖屏仍是「整屏推卡」——
  横屏 640dp 用推卡会把内容推到屏幕外，只剩一条空白。
- **短屏（高 < 480dp，手机横屏/分屏下半）**：
  - 顶栏 `ProferHeaderRow(compact = true)`：上下留白 0，行高 48→40，图标去掉圆键底，
    标题不再包浮层胶囊。40dp 靠 `LocalProferMinTouchTarget` 只在顶栏内部生效，
    正文与列表的按钮仍是 48dp；这是「状态栏 + 48dp 吃掉 360dp 高 20%」之后唯一能再收的地方。
  - 会话行与项目头在短屏收到 **48dp**（= 触控下限）：去掉上下留白，不缩热区。
    5 条会话能省出 40dp，正好是一条消息的高度。
  - 消息间距 24→16、列表顶部留白 12→8；裁切渐隐顶部 22→12、底部 14→8——
    渐隐是用来盖半行硬切的，宽了就会盖掉正常内容。
  - 欢迎页换紧凑档：标记 32、标题 titleLarge、描述 bodySmall，建议卡**固定 4 列一行**；
    按竖屏 32dp 留白排版会超出 360dp 视口，滚到中间时「连接电脑」正好被输入条遮住。
    2×2 会把第二排压到输入条下面，只能用一行；双栏时对话列只有 460dp，卡片更窄，
    字号降一档（labelMedium）并强制单行，否则「排查一个问题」换行、四张卡高低不齐。
  - 会话列表头只留模式胶囊 + 搜索 + 新建，**一律不显示「Profer」字**：
    320dp 列表栏放不下「品牌 + Agent + 搜索 + 新建」，品牌字会被压成 0 宽（真机 781dp 复现）。
  - **窄侧栏（< 260dp）再收一档**：连标记也收掉、内边距 12、间距 8→4、
    模式胶囊去掉箭头只留文字；**胶囊贴左、搜索/新建靠右**（品牌字收掉后左侧不能再留空把整组推右）；
    底部「书脚」的连接胶囊改成只写「已连接」，用 `weight(1f)` 在剩余宽度里省略，
    设置键保住 48dp 热区（否则会被挤成一条竖线）。
  - 内容区**不叠纸面渐变**，改用纯 `background`：渐变底部的色带会整条落在输入条下方，
    360dp 高里像一条抹不掉的脏边。竖屏与平板仍是 `proferBackdrop()`。
  - 横屏进入**沉浸式导航栏**：三键导航栏 48–56dp 不透明、对比度强制关不掉，
    会在输入条下方填出一整条系统色。收起后内容铺到窗口卡底边，上滑临时唤出
    （`BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`）；离开横屏立即 `show()`，竖屏不留副作用。
  - 底部弹层换成居中对话框（同双栏），底部弹层在 360dp 高里只能分到一条窄带。
- 「回到最新」**悬浮在消息区底部居中，不进 bottomBar**：它一旦占一行，360dp 高里
  就等于凭空吃掉一条消息（40dp ≈ 消息区 20%）。悬浮会盖住半行气泡，这是可接受的代价——
  它只在离开底部时出现，滚到底就消失。
- 内容区（顶栏、消息、输入条）限制 760dp 居中，宽屏下正文行长不失控；
  双栏时消息左右留白 16→24dp。背景铺满内容区，不出现两侧断层。
- 垂直铰链（书本式/双屏）：分栏线对齐铰链左侧，铰链宽度留白，正文不跨折痕。
  铰链在屏宽 25%–60% 之外时忽略，退回默认分栏。
- 水平铰链（帐篷/桌面模式）：可用高度只剩一半，退回单栏，整块内容停到铰链下方。
- 设置/连接等全屏页：顶栏与内容一起限制 760dp 居中，不出现「标题贴左、内容缩中间」。
- 设置页在双栏宽度下改成「左导航 220dp + 右内容（上限 640dp）」：手机那列长滚动照搬
  到平板，找「通知」要滚十屏。
- 弹层（审批、提问、模型/预设选择、输入条「+」、会话操作、上下文用量）在双栏宽度下
  从底部弹层换成居中对话框：宽 420–560dp、四周 28dp 圆角、最高 86% 屏高、内容自己滚动。
  底部弹层拉宽到 800dp 会变成一条横贯全屏的板子，按钮 500dp 宽、还贴着屏幕底边。
- `LocalProferWindowSize` 在应用根部注入一次（`ProferWindowSizeProvider`），
  设置/连接这些独立路由页才拿得到真实断点；只在 `PocketDrawerLayout` 里注入会让它们永远走单栏。

## 4. 无障碍与适配

- 触控 ≥48dp；语义标签与点击动作在同一节点。
- 字体 2× 不截断、不重叠：信息行可增高，设置选项纵向排列，审批动作固定在底部。
- 深浅色 parity：每个页面至少一个深色预览；语义色不靠透明度表达。
- 平板/横屏：按 3.7 判分栏（内容区 ≥420dp），内容最大宽度 760dp 居中；不把手机单栏无限拉宽。
  短屏横向布局不得依赖「刚好放得下」：顶栏、空态、欢迎页各有紧凑档。
- 尊重系统「移除动画」；关键信息不只在动画结束帧。

## 5. 验证

- 每个页面至少一个 `@Preview`，覆盖浅色、深色、2× 字号。
- debug 专用 `UiGalleryActivity` 提供真实 Compose 样本（无网络、无凭据、无用户数据）。
- 提交前：`test`、`lintDebug`、`assembleDebug`、`assembleRelease`、
  `connectedDebugAndroidTest`；截图来自 `adb exec-out screencap`。
- 新增视觉规则时同步更新本文件与 `UiDesignTokensTest` / `UiSystemRegressionTest`。
